## Overview

This document covers Apple Platform Single Sign-On and the broader Apple device management architecture relevant to Microsoft Intune-managed environments. Apple Platform SSO enables macOS devices to use Entra ID credentials for system-level authentication, replacing the need for separate local account passwords and providing a seamless SSO experience consistent with the Windows managed estate.

## Apple MDM Push Certificate

Before any Apple device can be managed through Intune, an Apple MDM Push Certificate must be configured. This certificate is issued by Apple and authorises Intune to communicate with Apple devices. It is created using a Certificate Signing Request generated by Intune, uploaded to the Apple Push Certificates Portal, and the resulting certificate is uploaded back to Intune.

The certificate must be renewed annually using the same Apple ID. If the Apple ID used for creation is lost or the certificate expires without renewal, all Apple device management in the tenant is disrupted and devices must be re-enrolled.

In this lab a dedicated Apple ID was created at dalmodernworkplacelab@gmail.com for this purpose, following enterprise best practice of using a shared IT team account rather than a personal Apple ID.

## Apple Platform SSO

Apple Platform SSO is configured through an Intune configuration profile using the Settings catalog. It maps the macOS local account to the user's Entra ID identity, enabling single sign-on at the operating system level. Once configured, the user authenticates to macOS using their Entra ID credentials and receives SSO tokens for all Microsoft 365 and Entra-integrated applications without additional prompts.

| Component | Description |
|---|---|
| SSO extension type | Microsoft Entra ID |
| Authentication method | Password or secure enclave key |
| Screen lock behaviour | Requires re-authentication after screen lock |
| Conditional Access integration | Device compliance state evaluated at authentication |

Apple Platform SSO is deployed as a Settings catalog configuration profile in Intune targeting macOS devices. It requires the Microsoft Enterprise SSO plug-in for Apple devices to be deployed as a managed app alongside the profile.

## Apple Business Manager

Apple Business Manager is a web portal operated by Apple for organisations managing Apple devices at scale. It requires registration with a valid DUNS number and an organisational email domain. Once registered, it enables two key capabilities not available through manual enrolment.

**Automated Device Enrolment** allows devices purchased through Apple or authorised resellers to be assigned to an MDM server automatically. When a new device is powered on for the first time it contacts Apple, receives the MDM server assignment, and begins enrolment without any user interaction. The device can be configured as supervised, giving IT significantly more management control than user-initiated enrolment.

**Volume Purchase Programme** allows organisations to purchase and distribute apps in bulk, deploying them silently to managed devices without requiring users to have personal Apple IDs.

## Enrolment Method Comparison

| Method | Requires ABM | Supervised | Use Case |
|---|---|---|---|
| Company Portal enrolment | No | No | BYOD and personally owned devices |
| Automated Device Enrolment | Yes | Yes | Corporate-owned devices purchased through Apple or authorised resellers |
| Apple Configurator | No | Yes | Corporate-owned devices not purchased through ABM |

In this lab environment Company Portal enrolment was used as the MacBook Air is a personally owned device. In a corporate environment where devices are purchased through Apple or an authorised reseller, Automated Device Enrolment would be the standard approach.

## Conditional Access Impact

macOS devices enrolled in Intune are subject to the same Conditional Access policies as Windows devices. The device compliance state evaluated by the macOS compliance policy is consumed by Entra Conditional Access policies requiring compliant devices. A macOS device that fails the compliance policy is blocked from corporate resources in the same way a non-compliant Windows device would be.

In this lab the macOS-Compliance-Baseline-Lab policy enforces minimum OS version 14.0, FileVault encryption, system integrity protection, firewall, and password requirements. A device failing any of these settings is marked non-compliant and access to corporate resources is blocked by the Conditional Access policy requiring compliant devices.
